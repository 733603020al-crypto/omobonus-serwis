### 1. Картинки (sharp из node_modules проекта)

- Пересжатие WebP/JPG q77–92 (ниже q77 смазывает пергамент — нельзя). Принимать вариант только если одновременно: PSNR ≥ 40 dB, худший блок 16×16 ≥ 32 dB, alpha ae ≤ 8, экономия ≥ 8% и ≥ 1,5 КБ. Иначе оставить оригинал.
- Не трогать: текстуры `parchment`/`papier`, `*-depth`, исходники, которые и так режет next/image.
- Анимированный WebP: все кадры, длительности, loop, disposal/blend — без изменений; пересжатие только если проходит те же пороги по кадрам (обычно уже на пределе). Mobile-версии анимаций в 1,5× меньше — видимая потеря, не делать.
- Размер не больше реального показа × DPR (иконки разделов 300 px нужны под DPR 2–3; логотипы — 3× DPR). PNG/WebP с прозрачностью — обрезать пустые поля.
- Отдельная mobile-версия — только если реально экономит (hero-фон уже отдельный AVIF ~20 КБ).
- AVIF→WebP не переводить (тяжелее). Бэкап оригиналов — в scratchpad, до замены.
- После замены файла под тем же именем — убедиться, что браузер отдаёт новый файл (размер/Last-Modified).
- Визуальный контроль: скриншоты до/после 390/1440, попиксельное сравнение.

### 2. Первый экран и загрузка

- Hero/LCP-картинка: есть в HTML, `fetchPriority="high"`, не lazy; первый слайд карусели — preload, остальные — lazy/после загрузки.
- Карусели: первый кадр нового файла не крупнее главного; уходящий слайд держит полный файл до конца движения (стабильный LCP, ЭТАП 142б/в). Пауза каруселей вне экрана.
- Анимированный hero — только через `AnimatedHeroImage`: сначала статичный кадр, анимация после load + простоя + 2,5 с; reduced-motion — анимация не грузится.
- **Не грузить то, что сейчас не нужно** (решение пользователя 2026-10-30). Карусели и блоки ниже первого экрана: сразу — только видимое; после загрузки — только ближайшие следующие слайды; остальное (в т.ч. видео/анимации далёких слайдов) — когда слайд на 2–3 шага от показа. Не хватает времени на подгрузку — **увеличить показ слайда даже на 1 с**, если это даёт выигрыш в скорости; пустого слайда быть не должно (тик пропускается, пока следующий не в кэше).
- Ниже первого экрана — `content-visibility` (отзывы, футер, секции); нельзя на ленте логотипов (обрезает).
- Карта в футере — не грузится до прокрутки.

#- **Хронология загрузки (обязательная проверка для каждой страницы).** Из Lighthouse JSON (`network-requests`) или Playwright выписать все запросы крупнее ~30 КБ по времени старта: что грузится до первой отрисовки, что сразу после `load`, что позже. Для каждого запроса ответить: нужен ли он прямо сейчас? когда пользователь его реально увидит (слайд — через сколько секунд, блок — через сколько экранов прокрутки)? Если не нужен сейчас — отложить до «за 2–3 шага/1,5 экрана до показа» (карусель — по номеру слайда, блок — по прокрутке); при нехватке времени увеличить показ слайда. Так найден ролик струйного принтера (270 КБ), который грузился сразу после `load` за 11 с до показа (ЭТАП 190). После правки: сверить, что запрос ушёл позже, ролик/картинка успевает загрузиться до показа, пустого слайда нет (Playwright: время запроса и состояние на показе), вес при загрузке уменьшился. Проверять каждую карусель (главная, услуги, wysylkowy) — копии каруселей живут отдельно и могут отличаться.

## 3. Скрипты и гидратация

- Страница входит в область `scripts/defer-hydration.mjs` (скрипты после первого кадра; сейчас все страницы PL/UK/RU). Новый slug/маршрут — проверить, что покрыт.
- Тот же скрипт убирает копию CSS/JSON-LD из RSC-данных HTML — проверить на новой странице, что HTML не вырос (~на четверть легче).
- Прайс: одна разметка (не две mobile/desktop), закрытые секции без гидратации, данные/цены считаются на сервере.
- Логотипы, отзывы — без гидратации; золотая анимация на паузе вне экрана; GTM через requestIdleCallback; CookieYes lazyOnload.
- Клиентские компоненты (`use client`) не импортируют `@/lib/services-data` целиком (на /serwis-wysylkowy это был скрипт 583 КБ): нужные куски готовит серверный шаблон и передаёт props.
- Нет новых тяжёлых клиентских зависимостей/импортов; размер начального JS сравнить с соседней страницей услуги (услуги ~206 КБ gz, главная ~169 КБ gz).

### 4. CSS и шрифты

- `inlineCss` включён (выключение — хуже, проверено дважды).
- Шрифты: preload Cormorant с польскими буквами (latin-ext), Lora только на /kontakt, на телефоне мелкий текст — системный шрифт вместо Inter. Новых шрифтов/весов не добавлять.
- @keyframes — в `globals.css`, не runtime-`<style>`.

### 5. Замер скорости

- Prod-сборка в копии (git archive + junction node_modules в scratchpad), не в основном репо (build ломает dev-сервер).
- Lighthouse 13, mobile и desktop, Chrome с GPU-флагами `--headless=new --enable-gpu --use-angle=d3d11 --enable-gpu-rasterization --ignore-gpu-blocklist`.
- Медиана ≥ 5 прогонов; до/после — в одной серии A/B поочерёдно (копии на портах 3011/3012). Один низкий результат — не регресс (шум 60–95).
- Сравнить с базой: главная ~90–97, услуги 90–96, kontakt ~92, o-nas 86–92, polityka 98, regulamin 96; desktop 97–100. Новая страница — не хуже соседних услуг.
- Смотреть LCP-элемент, FCP, LCP, TBT, CLS (0–0,01), вес страницы и число запросов.
- Тестовый prod-сервер может зависнуть на пережатии AVIF — перезапустить, прогреть, потом мерить.
