# Передача чата

Цель: новый чат продолжает работу по короткой записи, без чтения истории. Новый журнал не создавать, чат не закрывать, коммит не делать.

## Что сделать
0. Определить проект: правки сайта — журнал `C:/Users/Andrii/omobonus-serwis/AI_WORK_STATE.md` (ветка `test`); правки Workspace — `C:/Users/Andrii/omobonus-workspace/AI_WORK_STATE.md` (ветка `Panel`). Навык общий для обоих проектов; записи разных проектов не смешивать.
1. В журнале проекта найти запись этой задачи (раздел `## … — <задача>`). Есть — править её, нет — добавить новую сверху: `## ГГГГ-ММ-ДД — Передача: <задача>`. Дубликаты не плодить.
2. Заполнить пять пунктов, каждый 1–3 строки, только то, что нельзя восстановить из кода и git: **Задача** (что и зачем); **Решено** (утверждённое владельцем, с датой); **Запреты** (что не делать); **Изменено** (файлы и результат проверки; незакоммиченное отметить); **Дальше** (один следующий шаг и открытые вопросы).
3. Не копировать в запись длинные логи, отвергнутые варианты и то, что уже есть в журнале или правилах — дать ссылку на раздел.
4. Записать метку для нового чата: `node C:/Users/Andrii/omobonus-workspace/scripts/handoff.mjs "<заголовок записи>"`. Хук в первом запросе нового чата сам напомнит прочитать эту запись.
5. Проверить: запись видна в журнале проекта (все пять пунктов, «Дальше» заполнен), метка записана без ошибки. Не прошло — исправить и проверить снова; о переходе в новый чат не говорить.
6. Только после успешной проверки, сам, без просьбы пользователя, ответить дословно: «Контекст сохранён. Закрой этот чат, открой новый и напиши „продолжай“. Работа продолжится с того же места». Не предлагать переход до этого момента.

## В новом чате
Прочитать только указанный раздел журнала проекта — `AI_WORK_STATE.md` сайта или Workspace, где найдётся заголовок из метки (не весь файл), проверить `git status` и продолжить с пункта «Дальше». Если запрос пользователя о другой задаче — метку игнорировать.
