# Запуск новой страницы: порядок и чек-лист

## Что это
Единый порядок, как создаётся и запускается новая страница услуги. Раньше он был разбросан по журналу работ и памяти. Страницу никогда не пускаем сразу на сайт: сначала отдельная ветка, потом проверки, потом ваше «да».

## Главное
- Новая страница делается отдельно от основного сайта, в своей ветке `pages/<название>`, в своей рабочей копии и на своём порту. Основной сайт при этом не трогаем.
- Пока вы не разрешили, страница закрыта от Google, нет в меню и на главной.
- Вам всегда сообщаю, чего не хватает: если у раздела нет своей картинки, ставлю нейтральную заглушку и прошу вас прислать картинку. Чужую по смыслу картинку не подставляю.
- Перед запуском обязательно: проверка скорости, проверка вида на телефоне и компьютере, проверка всех языков (польский, украинский, русский, английский).
- Цены, сроки и тексты согласуете вы. Заголовки и описания для Google утверждаются в SEO-панели, сам их не меняю.
- В основную ветку «тест» страница попадает только после вашего разрешения. В «мастер» отправляете вы сами.

## Порядок шагов
1. Создать ветку и отдельную рабочую копию со своим портом (с вашего согласия).
2. Собрать каркас по образцу соседней услуги: те же блоки, прайс, вопросы и ответы, форма.
3. Подготовить картинки (иконки разделов, карусель, картинка для соцсетей) по стандарту «Анимации и картинки».
4. Написать тексты на польском, затем синхронизировать украинский, русский и английский.
5. Проверить вид и скорость, исправить найденное.
6. Показать вам ссылкой на страницу. Дальше — ваши правки.
7. По вашему разрешению влить в «тест», затем (отдельно) открыть для Google, добавить в меню и на главную.
8. Запись в журнал работ и в «Утверждённые решения», если принято что-то важное.

## Для Claude (техническое)

### Ветка и копия
- Ветка `pages/<slug>` от актуального `test`; отдельный worktree в `C:\Users\Andrii\omobonus-<имя>` со своим портом (3001+, без turbopack, если не нужно). Создание ветки — по согласованию (CLAUDE.md, «Ветки»). Правки страницы — только в её ветке.
- Перед работой: `git fetch`, ветка соответствует задаче, `git status --short` чистый. Одна сессия — одна папка.

### Каркас и данные
- Образец — ближайшая по типу страница услуги; общие шаблоны, не копирование JSX. Данные услуги — `src/lib/services-data*.ts`, метаданные — `services-meta-shared.ts`; цены/сроки в одном месте для pl/uk/ru/en (`services-pricing-data.ts`, проверка `npm run check:i18n-sync`).
- Обязательные блоки: hero (через `AnimatedHeroImage`/карусель по стандарту), аккордеон с прайсом, окно «Kategorie urządzeń» (`PriceTooltipContent`), FAQ, форма, связанные услуги (`relatedServiceSlugs`).
- Стандарты, по которым проверять страницу: прайс — `.claude/rules/price-card-standard.md`; окно категорий — `docs/kategorie-urzadzen-standard.md`; FAQ — `.claude/rules/faq-answer-standard.md` и `docs/standards/faq-cards.md`; диагностика и оплата — `docs/diagnoza-i-platnosci-standard.md`; дизайн — `.claude/rules/design-guardrails.md`.
- Иконка слота подкатегории задаётся через `subcategory.icon`, не по title. Нет подходящей картинки — заглушка и прямая просьба прислать картинку.

### Картинки
- По `docs/animations-images-standard.md`: пороги пережатия, обрезка пустых полей, версионные имена, бэкап оригиналов, первая картинка карусели заменяет главную везде (карусель, og:image, manifest, `KANONICZNY_MANIFEST`, иконка меню, card-icon).

### Языки и SEO
- PL — источник; UK/RU/EN синхронизируются, не переводятся построчно; проверка общего шаблона минимум на PL и UK (`docs/languages/languages-standard.md`, `docs/languages/nowy-jezyk-standard.md`).
- Пока страница не утверждена: `noindexSlugs` содержит slug (в `[slug]/page.tsx` всех языков и в `sitemap.ts`) — robots noindex, нет в sitemap. Title/Description/OG/Twitter — отдельно, только после утверждения в SEO-панели.
- Запуск в индекс (по отдельному разрешению): убрать slug из `noindexSlugs`, проверить canonical на свой язык, hreflang pl/uk/ru/en + x-default, URL в sitemap. URL/slug после согласования не менять.
- Включение в меню «Usługi», на главную (слайдер `home-hero-showcase`) и в списки связанных услуг — только по согласованию. Если страница связана с кнопками на главной/услугах (как «Serwis wysyłkowy»), напомнить про ссылки кнопок.

### Скорость (обязательно до слияния)
- Полный чек-лист — `.claude/rules/optimization-check.md`; закрытое и откатанное — `docs/optimization-knowledge.md`.
- Проверить, что slug покрыт `scripts/defer-hydration.mjs` (область `uslugi`) и HTML не вырос; нет новых тяжёлых клиентских зависимостей; начальный JS не хуже соседней услуги (~206 КБ gz).
- Prod-сборка — только в отдельной копии, не в основной папке (build ломает dev-сервер). Lighthouse mobile/desktop, медиана ≥ 5 прогонов; новая страница не хуже соседних услуг (90–96 на телефоне).

### Проверка вида
- Одна финальная проверка 1440 и 390 px: горизонтального скролла нет, меню и язык работают, категории прайса и подсказки открываются, карусели идут полный круг, битых картинок 0. Для PL, UK, RU, EN. `npx tsc --noEmit` и сборка копии — без ошибок.

### Слияние и публикация
- Влить в `test` только по разрешению, быстрым пушем: `git fetch; git merge-base --is-ancestor origin/test HEAD; git push origin HEAD:test`.
- В `master` отправляет пользователь (защита блокирует); дать одну строку для терминала, затем проверить боевой сайт.
- После запуска: запись этапа в `AI_WORK_STATE.md`, дата проверки оптимизации в шапке, итог в `docs/decisions.md`, если принято постоянное решение; рабочую копию и ветку удалять только после проверки, что всё влито, и с разрешения.
