# Скорость сайта: что работает, что нет

## Что это
Накопленное знание о скорости, вынесенное из длинного журнала работ. Читать перед любой работой над скоростью, чтобы не повторять закрытое и откатанное. Чек-лист проверки (раз в месяц и для новой страницы) — в «Проверке оптимизации».

## Пять главных выводов
- Цель достигнута: телефон 90–98 на большинстве страниц (главная ~90–97, услуги 90–96, контакты ~92, «О нас» 86–92, политика 98), компьютер 97–100.
- Главный рычаг — скрипты загружаются после первого кадра. Измеритель считает всё, что началось до первой отрисовки (~1,4 с), поэтому «отложить на полсекунды» не помогает, помогает уменьшить объём до первой отрисовки.
- Мелкие приёмы выигрыша не дали и откатаны (список ниже). Не повторять без новой причины: изменённого кода, регресса или вашей просьбы.
- Один результат замера — шум (на одном коде 58–85). Верить только медиане минимум 5 прогонов, сравнению «до/после» поочерёдно на одной машине.
- Менять только то, что даёт устойчивый выигрыш; вид, тексты, цены и адреса при ускорении не трогаем.

## Как мерить
- Сборка — только в отдельной копии проекта, не в основной папке.
- Минимум 5 прогонов, медиана; варианты A/B — две копии на разных портах, поочерёдно.
- Одно низкое значение — не регресс. Если сервер копии завис на картинках — перезапустить и прогреть.

### Закрыто — повторно не проверять
- Скрипты после первого кадра — `scripts/defer-hydration.mjs` (этапы 116, 125, 142, 149): после сборки чанки Next заменяются загрузчиком после FCP; покрыты все страницы PL/UK/RU. Тот же скрипт убирает копию CSS и JSON-LD из RSC-данных (128, 131): HTML ~на четверть легче.
- Прайс: закрытые секции без гидратации (115), одна разметка вместо двух mobile/desktop (132), без перестройки после загрузки (130). Пре-меню открывается до загрузки JS (117).
- content-visibility ниже первого экрана (113, 114); на ленте логотипов нельзя — обрезает.
- Гидратация и сторонние скрипты (129–131): золотая анимация на паузе вне экрана, лента отзывов на Web Animations, логотипы и отзывы без гидратации, GTM через requestIdleCallback, CookieYes lazyOnload.
- LCP каруселей (142б, 142в): первый кадр нового файла не крупнее главного, уходящий слайд держит полный файл до конца движения.
- Картинки: вес оптимален (79–84), логотипы 3× DPR, hero-фон — отдельный mobile AVIF ~20 КБ, mobile-версии анимаций 1,5× = видимая потеря.
- Шрифты (93): latin-ext нужен; шрифты variable; убирать preload Inter — хуже. @keyframes — в `globals.css`, не runtime-`<style>` (94).
- inlineCss оставить включённым (16, 92, 115). Мёртвый CSS ~3,5 КБ — не стоит.
- Зависание AVIF на тестовом prod-сервере — сбой копии, лечится перезапуском; не расследовать.
- Desktop после мобильных оптимизаций не ухудшился (95–100): 54 комбинации. Повторять только при новых изменениях.

### Откатано — не повторять в том же виде
- inlineCss:false (главная 97→82); `<link>` вместо inline CSS.
- Урезание встроенного CSS до правил первого экрана (даже идеальное: +2–3 пункта в шуме, риск каскада).
- Отложенная гидрация прайса целиком; содержимое секций прайса только при открытии; дедупликация данных прайса; вырезание HTML закрытых секций (158).
- Отложенные картинки ниже первого экрана (97) и отложенные фоны пергамента/отзывов (22, 23).
- Упрощение эффектов на телефоне: тени, свечение, маски, золотые блики (96).
- Ленивые Radix Tooltip/Popover (88, 94); свой AccordionContent без Radix (26); отложенное меню, split чанка, will-change, npm dedupe (88).
- AVIF→WebP (тяжелее); убрать preload Inter; удалять веса шрифтов (93).
- Карусель «после первой отрисовки» (114) — хуже LCP; canvas вместо 40-кадровой анимации (21) — хуже качество.
- Футер без гидратации (131) — риск для формы и ссылок.
- Потолок-тест «без JS» (98): даже полностью без скриптов 85–86 — одним JS 90 не достичь.
