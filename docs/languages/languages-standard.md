# Языки и перевод

## Главное
- Польский — источник. UK/RU/EN — переводы. Язык существует, только если его страницы есть в проекте (EN не предполагать по упоминаниям).
- Польский изменился (текст, заголовки, кнопки, порядок/состав блоков) — синхронизировать UK/RU/EN с **текущим** PL, не со старым переводом. В том же проходе, тем же ИИ.
- Перевод верный, не «улучшенный»: без новых услуг и обещаний, без потери картинок и смысла.
- Ошибка в PL — сначала показать пользователю, после «да» исправить сразу во всех языках.
- Видимый текст в общих компонентах (подписи hero, значки, карточки, кнопки, UI) — из props/data/i18n, не жёстко на одном языке; PL и дизайн не менять.
- После правки текста — 390 px: кнопки, заголовки прайса, меню без обрезаний, «…», горизонтальной прокрутки.
- Адреса, slug, canonical, hreflang, sitemap, robots.txt — только с согласия пользователя (кроме явной части задачи); смена механизма — остановиться и спросить.
- Маршруты: PL `/`, `/uslugi/...`, `/kontakt`, `/regulamin`, `/polityka-prywatnosci`; остальные `/uk`, `/ru`, `/en`.
- Утверждённые Title, Description, заголовки без новой причины не пересматривать.

## Как переводим
- UK и RU — по смыслу PL, не друг с друга. EN — только с PL (UK/RU — образец структуры).
- Смысл PL: WSJP PAN. Естественность: RU — Грамота.ру; UK — Словник української мови, СЛОВНИК.ua; EN — Oxford, Cambridge, Merriam-Webster. Затем сверить с терминами сайта.
- Не уверен в формулировке — спросить, не угадывать.
- После работы искать чужой текст: подписи, надписи над разделами, значки, подсказки форм. На UK — польские буквы (ąćęłńóśźż) недопустимы.

## Каждая языковая страница
- canonical на себя.
- hreflang на все существующие версии + x-default на PL; на несуществующие не ссылаться.
- Правильный `lang`.
- В sitemap только существующие страницы.
- Title, description, H1, текст, услуги, FAQ — в коде страницы, не подгружать скриптом (динамически можно второстепенное: отзывы Google).

## Новый язык XX
- Карты Google (подвал, «Koszt dojazdu»), флаг, письма, отзывы — таблица в `docs/languages/nowy-jezyk-standard.md` (раздел 2).
- `npm run check:i18n-sync` падает без `mapa-XX.webp` или `mapLang` и пишет нужную команду.

## Цены и сроки: единый источник для pl/ru/uk
Читать перед правкой цен, сроков и текстов в `services-data*.ts`.

- Числа цен и сроков всех услуг (510 позиций) — только в `src/lib/services-pricing-data.ts` (`migratedPrice`/`migratedDuration`: `slug::section[.subcategory].index` → `{ wrapperKey, numbers }`). Одна правка — все языки.
- Текст вокруг чисел («od», «+ część», «GRATIS»…) — `src/lib/services-pricing-wrappers.ts` (`PRICE_WRAPPERS`/`DURATION_WRAPPERS`, плейсхолдеры `{0}`). Новый формат — новая запись там, не точечный текст в языковом файле.
- Итог собирают `getDisplayPrice`/`getDisplayDuration` (`src/lib/services-pricing.ts`); `service-accordion.tsx` вызывает только их. `item.price`/`item.duration` в `services-data*.ts` — fallback и документация.
- Менял число — обнови `item.price`/`item.duration` во всех трёх языковых файлах (иначе `check:i18n-sync` падает).
- Числа в PL/RU/UK файлах отдельно не хардкодить.
- Правка текста/структуры в одном языке → перевод на остальные два в том же ответе. Отдельной системы перевода на сайте нет.
- Состав секций/подкатегорий/позиций: `section.id`, `subcategory.id` и порядок совпадают 1:1 в `services-data.ts`, `-ru.ts`, `-uk.ts` (позиционный id считается по индексу).
- Перед коммитом, затрагивающим `services-data*.ts`, `services-pricing-data.ts`, `services-pricing-wrappers.ts`: `npm run check:i18n-sync` (`scripts/check-i18n-sync.ts`; exit 0 + «OK» — можно; иначе исправить расхождения).

### Частые ошибки
1. Ветка логики по польскому тексту (`row.label === 'Czynsz wynajmu…'`) — молча ломает RU/UK. Ветвиться по `rowIdx`/index/id; структуру текста распознавать языконезависимым regex.
2. При переводе проверять данные после build-time фильтров PL (пример: `naprawy-tasma` в `serwis-drukarek-laserowych`, `applyLaserElectronicsSubcategory`): id и count совпадают после преобразований.
3. `WynajemTable.tsx` — отдельный хардкод чисел (`plan1/2/3`), сейчас не рендерится; уберут `priceTiers` — включится. «Не используется» проверять по реальным данным, не по чтению кода.
4. После миграции искать `rg` неиспользуемые экспорты и устаревшие комментарии.
