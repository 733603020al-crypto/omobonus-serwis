# Анимации и картинки: стандарт

## Что это
Единые правила для анимаций, каруселей и картинок на сайте. Собраны из решений, которые вы уже принимали; применяются на всех страницах и языках.

## Главное
- Анимация вверху страницы не должна тормозить первый экран: сначала виден неподвижный кадр, анимация стартует позже.
- Карусели: первый слайд грузится сразу, остальные — после загрузки страницы; размеры слайдов вы называете сами, я их не подбираю.
- Золотые кнопки — один общий эффект; зелёная кнопка телефона в шапке остаётся зелёной (золотой эффект вам не понравился).
- Картинки: лёгкие, без видимой потери, без лишних пустых полей, в нужном размере; оригиналы сохраняются; новая версия — под новым именем файла.
- Нет подходящей картинки — ставлю нейтральную заглушку и прямо говорю, что нужна картинка. Чужую по смыслу картинку вместо неё не подставляю.
- Готовая картинка уже есть в проекте — беру её, копии не делаю.

## Для Claude (техническое)
Источники: `.claude/rules/optimization-check.md` (разделы 1–2), этапы 142б/в и 193 в `AI_WORK_STATE.md`, память пользователя (карусели, картинки, логотипы). Подготовка картинок в общем виде — `docs/claude/sajt.md`, «Растровые изображения».

### Анимации
- Анимированный hero — только через `AnimatedHeroImage`: сначала статичный кадр, анимация после load + простоя + 2,5 с; при reduced-motion анимация не грузится. Единое правило для всех услуг (компьютерная версия 59–61 → 71).
- Золотая анимация ставится на паузу вне экрана (GoldAnimationPause). @keyframes — в `globals.css`.
- Золотые CTA (`GOLD_CTA`) — эффект Shiny Button (`.gold-shiny` в `globals.css`, этап 193). Зелёная кнопка телефона в шапке — без золотого эффекта.
- Mobile-версии анимаций в 1,5× меньше — видимая потеря, не делать. Canvas вместо покадровой анимации — не делать (хуже качество).

### Карусели (HeroPrinterCarousel)
- Первый кадр нового файла не крупнее главного; уходящий слайд держит полный файл до конца движения; пауза вне экрана.
- Первый слайд — сразу с высоким приоритетом (preload), остальные — lazy/после загрузки. Не ломать.
- Замена/создание карусели: слайды по номерам файлов из папки пользователя; новые имена (…-v3-0N.webp), обрезка по alpha>3%, max 512 px, webp q92; старые файлы удалять после проверки использования.
- Первая картинка заменяет старую главную картинку услуги везде: карусель, og:image (services-meta-shared), manifest.ts, KANONICZNY_MANIFEST, иконка меню (126 px), card-icon.
- Размеры слайдов (мал 0.74/0.76, сред 0.85, больш 0.95) самому не подбирать — спросить пользователя списком по номерам.

### Картинки
- Пересжатие WebP/JPG q77–92 (ниже 77 смазывает пергамент). Принимать вариант, только если одновременно: PSNR ≥ 40 dB, худший блок 16×16 ≥ 32 dB, alpha ae ≤ 8, экономия ≥ 8% и ≥ 1,5 КБ; иначе оставить оригинал.
- Не трогать: текстуры `parchment`/`papier`, `*-depth`, исходники, которые и так режет next/image. Анимированный WebP — все кадры, длительности, loop, disposal/blend без изменений.
- Размер ≤ реальный показ × DPR (иконки разделов 300 px под DPR 2–3; логотипы 3× DPR). PNG/WebP с прозрачностью — обрезать пустые поля. AVIF→WebP не переводить.
- Бэкап оригиналов — вне проекта до замены; после замены под тем же именем убедиться, что браузер отдаёт новый файл. Визуальная сверка 390/1440 попиксельно (в проверке оптимизации).
- Номера фото с рабочего стола — указатель: найти такой же файл в `public/images` по изображению и подставить, копий не делать.
- Иконка слота подкатегории — через `subcategory.icon`, не по title; сначала готовая подходящая картинка, потом заглушка; у нового раздела без картинки — сказать пользователю и попросить картинку.
- Логотипы бегущей строки: только официальный источник, сверять бренд, белые версии, метрики дописывать вручную (`scripts/brand-logo-metrics.mjs`).
