# Занеси в правила

**Перед ответом сверить 5 пунктов:** файл темы записан; дерево `pravila.md` и панель обновлены; в ответе есть ссылка; в ссылке есть `hl`; новое правило или навык проверено на ненужную постоянную загрузку (раздел ниже).

## Куда и как
- Сначала ищу по ключевым словам во всех файлах правил (`CLAUDE.md`, `docs/claude`, `docs/standards`, `.claude/rules`). Правило уже есть — дополняю его, новое не пишу. В ответе показываю, где искал и что нашёл; без этого запись не закончена.
- Тему нахожу по дереву в `docs/claude/pravila.md`, пишу в файл этой темы, в подходящий раздел. Не дублирую. Темы нет — спрашиваю.
- Правило продиктовано владельцем — формулирую коротко и пишу сразу. Правило придумал я сам — сначала показываю черновик (раздел и текст) и пишу только после согласия владельца. Безопасность, мастер, цены — сначала спрашиваю.
- 1–3 строки на правило. Только указания для действия: без «что это», «зачем», примеров, дат, пометок «утверждено» и истории.
- Файл: заголовок; разделы по темам; в разделе — короткие указания «что, где, когда»; таблица только для «если X → Y».

## После записи
- Добавляю правило в дерево (`pravila.md`) и в список панели (`omobonus-workspace/app/src/lib/rules-groups.ts`). Без этого правило считается не записанным.
- Описание в панели: сначала ключевые слова команды в кавычках (как в списке `pravila.md`), потом одна короткая фраза, что делает Клод. Нет команды — вместо слов ситуация («При работе с Title»). Без оговорок и исключений. Пояснения для человека — только там, не в файле.
- В `hl` брать начало правила до первого знака разметки (`` ` ``, `*`, `[`), иначе подсветка не найдёт текст. Ссылку и подсветку давать всегда, ответ без них — не закончен.
- Ссылку не угадывать: `id` брать только из `RULE_FILES` по пути изменённого файла; перед отправкой проверить командой `curl "http://localhost:5180/api/seo-rules?name=<id>"` — ответ должен содержать текст из `hl`. Не нашёл `id` или текста нет — ссылку не давать, сначала исправить (добавить файл в `RULE_FILES` и в `rules-groups.ts`).
- Любое изменение правила (правка, уточнение, отмена, перенос), даже если пользователь не говорил «занеси в правила», заканчивается ссылкой с `hl` на изменённое место. Без ссылки ответ не отправлять; если правил изменено несколько — ссылка на каждое.
- Ответ: «Правило добавлено» (при правке — «Правило изменено»), записанная формулировка, ссылка `http://localhost:5180/seo/rules/<id>?hl=<первые слова правила, пробелы как %20>`. id — в `RULE_FILES` (`omobonus-workspace/app/server/workspace-api.ts`). Место словами не описываю.

## Проверка на постоянную загрузку (обязательно для каждого нового правила и навыка)
- Что грузится в каждый чат: `CLAUDE.md`, файлы `.claude/rules/` без строки `paths:` в начале, описания всех навыков и агентов. Правило без `paths` тратит токены даже там, где не нужно (случай optimization-check: ≈4,5 тыс. токенов в каждом чате).
- Как проверить: оценить размер (байт ÷ 4,5 ≈ токены) и запустить в корне проекта: `for f in .claude/rules/*.md; do head -8 "$f" | grep -q '^paths:' || echo "ВСЕГДА: $f $(wc -c <"$f") байт"; done`. Файл из списка «ВСЕГДА» больше ~2 КБ и нужен не в каждой задаче — исправить. Для навыка: описание короткое (1–3 предложения) и называет все ситуации вызова.
- Как исправить: нужно при работе с файлами — добавить в начало `paths:` с масками. Нужно по задаче (проверка, замер, процедура) — перенести в навык `.claude/skills/<имя>/SKILL.md` без изменений текста; в описании перечислить все ситуации вызова; в `CLAUDE.md` или файле темы написать «сначала вызвать навык»; обновить ссылки, `RULE_FILES`, `rules-groups.ts`, `kb.mjs`. Затем повторить команду, сверить текст (`cmp`) и размер старта в `/context`.
- Запись об исправлении — в журнал «Экономия токенов» (`knowledge/v2/4-panel-i-instrumenty/4-4-ekonomiya-tokenov/7-zhurnaly/zhurnal-optimizacii-tokenov.md`).

- Личная память — только для личных предпочтений; правила проекта — в этих файлах.
