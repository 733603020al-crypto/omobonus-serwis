# Среда: сервер, команды, субагенты, карточка Google

## Локальный dev-сервер

Проект должен быть доступен на `http://localhost:3000` во время и после задач.

Используй `npm run dev:turbo` (не `npm run start`, если явно не нужна проверка production-сборки). Не останавливай уже работающий сервер без необходимости; если пришлось остановить/перезапустить — обязательно запусти снова перед завершением задачи. Не оставляй несколько dev-серверов одновременно; не открывай отдельное внешнее окно терминала. Перед завершением проверь, что `http://localhost:3000` реально отвечает.

## Команды и Antigravity/IDE-подтверждения

Запускай команды напрямую из текущей директории (workspace уже открыт в корне) — не добавляй `cd C:\...`, если терминал уже там. Предпочитай простые отдельные команды из allow-list (`npx tsc --noEmit`, `git status --short`, `git diff --stat`, `git branch --show-current`, `rg`, `find`, `ls`, `node -e`) вместо длинных compound-команд с pipes/`;`/`cd`/`Select-Object -Last` — это снижает число системных подтверждений Antigravity/IDE. Если IDE всё равно запрашивает подтверждение безопасной команды — это не вопрос Claude к пользователю; после разрешения среды продолжай выполнение, не меняя план. Сборку (`npm run build`) запускай только в отдельной копии проекта (см. «Git»), чтобы не нарушить работающий сайт на localhost:3000.

Не используй `/lint` как skill — сначала проверь `package.json` на реальный npm-script и запускай его напрямую, если он есть.

## Специализированные субагенты

В `.claude/agents/` — 6 субагентов: `ui-design`, `pages`, `seo-content`, `performance`, `tech`, `karta-google` (карточка Google: отзывы, посты, фото, проверка), у каждого своя память (`memory: local`). Claude сам определяет область задачи и делегирует подходящему субагенту, когда это реально экономит основной контекст; не вызывает несколько субагентов без необходимости и не грузит чужую память «на всякий случай». Простые мелкие задачи, где субагент обошёлся бы дороже своей пользы, Claude делает сам напрямую (см. «Сохранение состояния и решений» выше). Цель — экономия токенов, а не число вызовов агентов.
