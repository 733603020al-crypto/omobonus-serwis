# Работа с сайтом: страницы, прайс, окна, документы, скорость

Задачи передаю помощникам: внешний вид (картинки, цвета, анимации, мобильная версия) — `ui-design`; состав и тексты отдельных страниц и услуг — `pages`; скорость загрузки — `performance`. Файлы: `.claude/agents/`.

## Изменение сайта

Не давай длинный план перед каждой правкой (короткий план — только если задача неоднозначная/рискованная/затрагивает критичные области). Меняй минимальное количество файлов, без рефакторинга «заодно». Не меняй цены, контакты, юридический смысл текста, отправку формы без подтверждения. Тексты и SEO можно менять, если задача явно про это. Дизайн-правки — только нужный UI-блок, без изменения архитектуры без необходимости. Архитектурный refactor — можно менять общие шаблоны и связанные route/data-файлы, если это прямо относится к задаче.

Специализированная логика по дизайну/языкам/SEO — в path-scoped `.claude/rules/design-guardrails.md` и `.claude/rules/i18n-seo-guardrails.md` (подгружаются автоматически при работе с соответствующими файлами) и в субагентах `ui-design`, `pages`, `seo-content`. Многоязычность: PL — source of truth, Claude синхронизирует версии, а не переводит по строкам; общий шаблон проверяется минимум на PL и UK; будущие языки — через общие шаблоны и i18n/data, не копированием JSX. Новый язык сайта (DE и др.) — по инструкции `docs/languages/nowy-jezyk-standard.md`. Архивный подробный справочник (на случай, если в rules/agents не хватило деталей): `claude-instrukcii/claude-dizain.md`, `claude-instrukcii/claude-mnogoyazychnyi-sait-i-seo.md` — открывать вручную по необходимости, не грузится автоматически.

## Проверка оптимизации

Раз в месяц и для каждой новой страницы (до слияния) — проверка скорости и веса по `.claude/rules/optimization-check.md`. Дата последней проверки — в шапке `AI_WORK_STATE.md`; если прошло больше 30 дней — в начале сессии напомнить пользователю и предложить проверку.

Новая страница создаётся сразу с оптимизацией по `.claude/rules/optimization-check.md`, ничего не пропускаем. Перед слиянием проверяем скорость: mobile и desktop, медиана из 3 прогонов, сравнение с соседней страницей услуги. Безопасные улучшения применяем сразу, не спрашивая; рискованные (меняют вид, тексты, цены, URL) — спрашиваем.

## Растровые изображения: подготовка (общее для всех ИИ)

- Любую картинку от пользователя (в том числе очень большую) перед вставкой в проект обязательно обрезаю, уменьшаю и сжимаю по пунктам ниже; исходник в проект не кладу. Без напоминания пользователя.
- Готовую картинку пользователя только обрезаю, уменьшаю и вставляю: не рисую заново, не перекрашиваю, не растягиваю. Сначала проверяю сам файл, в том числе прозрачность (прозрачное не превращать в чёрное). Не совпало с оригиналом — один раз сверяю с ним, не гадаю.
- При добавлении или замене картинок — минимальный разумный вес без заметной потери качества; WebP или AVIF выбирать по фактическому сравнению, не вслепую.
- Обрезать лишние прозрачные поля, сохраняя содержимое, тени, свечение, края и alpha-канал.
- Разрешение — под реальный размер показа и DPR.
- Использовать существующие инструменты проекта; оригиналы хранить до конца проверки.
- После замены — новое версионное имя файла и обновление всех ссылок (обход старого кэша).
- Проверять вид на компьютере и телефоне: без обрезки и смещения элементов.
- Оригиналы и дубликаты не удалять без проверки использования и отдельного разрешения.
