# Ветки, коммиты, безопасность

## Git: commit, push, ветки

Commit, push и merge — только после явного разрешения пользователя на соответствующее действие. Перед разрешёнными Git-изменениями: ветка соответствует задаче (см. «Ветки»); для `master` пользователь отдельно назвал конкретное действие; `git status --short` содержит только ожидаемые файлы задачи; нет изменений `.env*`; цены/контакты/форма/юридический текст менялись только по прямому заданию; если менялся код сайта — `npx tsc --noEmit` прошёл и сборка прошла (в копии, см. `.claude/rules/optimization-check.md` §5); для правок только инструкций и документов сборка не нужна. Commit message — короткий, по смыслу. Push выполняй только в явно названную пользователем ветку, каждый раз по отдельному разрешению.

`git add -A` — только после проверки `git status --short`, что там только ожидаемые файлы; иначе точечный `git add <path>`.

**Ветки:**
* `test` — правки, оптимизация и проверки существующего сайта.
* Новая страница — в отдельной ветке `pages/<название-страницы>` (можно в отдельной рабочей копии со своим портом). Создание ветки и включение страницы в `test`, меню или на главную — только по согласованию с пользователем.
* Любая другая ветка — только если пользователь явно назвал её для этой задачи.
* `master` — защищена, см. «Безопасность».

Перед изменениями молча проверь текущую ветку. Если она соответствует задаче по правилам выше — продолжай автономно, не спрашивай про ветку каждый раз. Если не соответствует — останови работу и ничего не меняй, спроси пользователя (не переключай ветку самостоятельно).

Если пользователь написал «не commit», «не push», «только аудит», «ничего не менять», «read-only» — обязательно соблюдай это ограничение.

## Безопасность

* Не читай `.env`, `.env.local`, `.env.production`, `.env.development`, ключи, токены, пароли, секреты без разрешения — даже в audit-режиме. Не выводи секреты в ответ.
* Не устанавливай новые пакеты без подтверждения. Исключение: `npm install` для восстановления библиотек по package-lock (без новых пакетов и без изменения package.json) — разрешён постоянно.
* Не запускай опасные команды: удаление файлов, очистка базы, `git reset/rebase/clean`, деплой и отправка секретов наружу.
* Ветка `master` защищена. Любые изменения, commit, push и merge разрешены только после моего явного согласия на конкретное действие. Общее разрешение работать над проектом не считается разрешением изменять `master`. Работай в ветке, подходящей для задачи (см. «Ветки»).
