# Стандарт Title — Omobonus

Постоянный инструмент проверки `<title>` страниц. Действует для главной и всех `/uslugi/*` на PL/UK/RU/EN.

| Что | Где |
|---|---|
| Правила, логика, процедура | этот файл |
| Утверждённые Title (69), исключения, история, отклонённые варианты | `docs/seo/title-decisions.json` |
| История проверок по вкладкам SEO-панели | `docs/seo/audit-history.json` |
| Проверка и сборка панели | `scripts/seo-audit/title-audit.mjs` |
| Вид панели | `scripts/seo-audit/panel-template.html` |
| Панель | Omobonus Workspace → `http://localhost:5180/seo` |

Где задаются Title на сайте: `src/lib/services-meta-{pl,uk,ru}.tsx` (`seoMetadata`), главная PL — `src/app/(pl)/page.tsx`. Суффикс добавляет шаблон layout.

## 1. Правила

1. **Шаблон услуги:** `Serwis i naprawa [устройства] | Omobonus Wrocław`.
   - UK: `Сервіс і ремонт [пристроїв] | Omobonus Вроцлав`.
   - RU: `Сервис и ремонт [устройств] | Omobonus Вроцлав`.
   - EN: `[Device] repair and service | Omobonus Wrocław` — естественный английский порядок слов (EN добавлен 2026-10-23; тексты ждут утверждения в панели).
2. **Суффикс** ровно один, стандартный: PL и EN ` | Omobonus Wrocław`, UK/RU ` | Omobonus Вроцлав`. В данных страницы суффикс не пишется (иначе он задвоится).
3. **Длина — ориентир 35–60 символов** с пробелами и суффиксом. Это не жёсткий лимит Google.
   - Не сокращать Title исключительно ради 60 символов, если это приводит к потере важного поискового запроса.
4. **Обрезка в Google** (Arial 20px):
   - ПК: 600 px. ✕ — если обрезаются ключевые слова, ◐ — если обрезается только хвост/суффикс.
   - Телефон: 330 px на строку, больше 2 строк — ◐.
5. **Без производителей** (Zebra, Dymo, HP, Canon…).
6. **Без лишних хвостов:** «— cennik / — ціни / — цены», служебные тире.
   - Скобки допустимы только как утверждённое пояснение термина (исключения ниже).
7. **Без повтора синонимов одного устройства** через «и/і/i/та/oraz». Например, «Ремонт UPS і джерел безперебійного живлення» нельзя.
   - Аббревиатура как пояснение термина повтором не считается: «Ремонт джерел безперебійного живлення UPS» можно.
8. **Естественность языка:**
   - формулировка такая, как люди ищут;
   - UK/RU не переводятся по словам с PL;
   - смысл совпадает с PL.

## 2. Утверждённые исключения (не пересматривать без новой причины)

| Страница | Почему не по шаблону |
|---|---|
| Главная PL/UK/RU | Общий формат «Naprawa komputerów, laptopów i drukarek» / «Ремонт комп'ютерів, ноутбуків і принтерів» / «Ремонт компьютеров, ноутбуков и принтеров» |
| outsourcing-it | Не ремонт: аутсорсинг/обслуживание IT |
| druk-3d-na-zamowienie | Не ремонт: печать на заказ |
| wynajem-drukarek | Аренда; «(dzierżawa)» — пояснение |
| drukarka-zastepcza | Подменный принтер; «(na czas naprawy)» — пояснение |
| naprawa-zasilaczy-ups UK/RU | Формат «Ремонт …»; «UPS» — пояснение термина |

Исключение хранится в поле `exception` у страницы в `title-decisions.json`. Проверки шаблона, производителей и хвостов к нему не применяются. Суффикс, синонимы и обрезка проверяются всегда.

## 3. Логика статусов в панели

**«Требуют решения»** — только:
- новая страница, которой нет в `approved`;
- утверждённый Title, который на сайте теперь другой. Предлагается вернуть утверждённый, можно отклонить и вписать свой;
- пункты из `pending` (новые предложения Claude, проверенные «свои варианты» пользователя).

**«Утверждено»** — утверждённые и неизменённые Title, даже если у исключения есть ◐ про обрезку хвоста. Уже согласованное не выносится повторно.

**Отклонённые варианты** (`rejected`) показываются под предложением с пометкой «Ранее отклонено — повторно не предлагаю». Claude их больше не предлагает. Общие отклонённые подходы — в `rejectedPatterns`.

Решение в панели действует только для того предложения, к которому принято. Если предложение поменялось, решение снимается.

## 4. Порядок согласования

- **Согласование:** любые изменения Title проходят исключительно через SEO-панель Omobonus Workspace (`localhost:5180/seo`).
- **Утверждение:** запрещено изменять Title на сайте без окончательного утверждения пользователя.

1. Пользователь в панели нажимает **Утвердить** (принять предложение Claude) или **Отклонить** и вписывает «Свой вариант». Суффикс добавится сам.
2. **«Скопировать решения для Claude»** → текст вставляется в чат.
3. Для каждого пункта Claude делает следующее:
   - **УТВЕРДИТЬ:** применяет Title на сайте и переносит его в `approved` (новый `stage`, `date`, запись в `history`).
   - **«Свой вариант»:** проверяет по правилам раздела 1. Свои варианты не применяются на сайте до окончательного утверждения.
     - Если вариант в порядке — кладёт его в `pending.review[url] = {own, status:"ok", why, exc?}`.
     - Если есть проблема — кладёт `{own, status:"fix", fix:"…", why}`.
   - Отклонённое предложение Claude дописывает в `rejected[url]`.
4. Claude пересобирает панель, пользователь утверждает повторно.
5. После применения на сайте `pending` очищается.

Формат `pending.proposals[url] = {title: "базовая часть без суффикса", exc?: "причина"}`.

## 5. Повторная проверка (для новой сессии Claude)

1. Ветка `test`, dev-сервер отвечает на `http://localhost:3000`.
2. `node scripts/seo-audit/title-audit.mjs` — скрипт выполняет по порядку:
   1. Берёт адреса из `sitemap.xml`: главная и `/uslugi/*` на PL/UK/RU.
   2. Читает текущие Title с сайта.
   3. Сравнивает их с `approved`, находит новые и пропавшие страницы.
   4. Считает, сколько Title требуют решения.
   5. Дописывает запись в `audit-history.json` (`tabs.title`: дата, страниц, проблем, список изменений с прошлой проверки) и обновляет `snapshot.title`. Повторный запуск в тот же день без изменений запись не дублирует.
   6. Собирает панель в `%TEMP%\omobonus-seo-panel.html`.

   `--dry` — без записи в историю.
3. Результат — в SEO-панели Omobonus Workspace `http://localhost:5180/seo` (если не запущена — `C:/Users/Andrii/omobonus-workspace/app/start-workspace.vbs`).
4. Для новых страниц и изменённых Title Claude делает следующее:
   - Если Title не по правилам — добавляет предложение в `pending.proposals` и пересобирает панель (`--dry`).
   - Если Title новой страницы по правилам — оставляет как есть: панель предложит утвердить текущий.
5. В ответе пользователю: сколько страниц проверено, что изменилось, сколько ждёт решения.
6. Сайт при проверке не менять. Commit и push — только по отдельному разрешению.

## 6. Остальные вкладки панели

Description — работает, стандарт в `docs/seo/description-standard.md`. H1, H2, H3, H4 — пока пустые, проверки не настроены. Аудит каждой — отдельной задачей.
- Когда вкладка заработает, её история пишется в `audit-history.json → tabs.<вкладка>`.
- Её стандарт и решения — в отдельных файлах `docs/seo/<элемент>-standard.md` и `docs/seo/<элемент>-decisions.json`, по образцу Title.
