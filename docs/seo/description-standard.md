# Стандарт Description — Omobonus

Постоянный стандарт meta description. Действует для главной и всех `/uslugi/*` на PL/UK/RU. Утверждён пользователем 2026-10-19, после внедрения 69 Description (коммит `11f3473`).

| Что | Где |
|---|---|
| Правила, исключения, методика, процедура | этот файл |
| Утверждённые Description (69), исключения, отклонённые варианты, предложения | `docs/seo/description-decisions.json` |
| Исследования по каждой услуге (выбранные и отклонённые работы, источники) | `docs/seo/description-research/<slug>.json` |
| История проверок | `docs/seo/audit-history.json` (`tabs.description`) |
| Проверка и сборка вкладки | `scripts/seo-audit/description-audit.mjs` |
| Автоматические проверки и вид панели | `scripts/seo-audit/panel-template.html` (лист Description) |
| Сервер панели | `scripts/seo-audit/serve.mjs` → `http://localhost:4100/#description` |

Где Description задаются на сайте:
- услуги — `src/lib/services-meta-{pl,uk,ru}.tsx` (`seoMetadata`);
- главная — `src/app/(pl)/page.tsx`, `src/app/uk/page.tsx`, `src/app/ru/page.tsx`.

**Утверждённые Description важнее шаблона.** Утверждённый текст не переписывается ради соответствия правилам. Если он расходится со стандартом, это выносится пользователю на решение. Новые исключения — только после отдельного согласования.

---

## 1. Правила

### Структура

1. **Шаблон страницы услуги:**
   - PL: `✔ Serwis i naprawa [urządzeń] we Wrocławiu ✔ [konkretne prace] ✔ Pełny cennik bez ukrytych kosztów ☎ 793 759 262`
   - UK: `✔ Сервіс і ремонт [пристроїв] у Вроцлаві ✔ [роботи] ✔ Повний прайс без прихованих витрат ☎ 793 759 262`
   - RU: `✔ Сервис и ремонт [устройств] во Вроцлаве ✔ [работы] ✔ Полный прайс без скрытых платежей ☎ 793 759 262`
2. **Три смысловых блока:** что и где (услуга и город) → какие конкретные работы → прозрачный прайс и телефон.
3. **Символы `✔` и `☎` — утверждённый формат.** Блоки начинаются с `✔`, телефон — с `☎`. Других эмодзи нет. Символы не убираются автоматически, даже если Google иногда меняет вид сниппета.
4. **Оформление.** Работы перечисляются через запятую, последние две можно соединить «i / і / и». Каждый блок начинается с заглавной буквы. Точки в конце нет.
5. **Город обязателен на всех страницах**, включая главную, хабы и общие страницы: PL `we Wrocławiu`, UK `у Вроцлаві`, RU `во Вроцлаве`.
6. **Телефон обязателен** — в конце текста: `☎ 793 759 262`.
7. **Концовка обязательна и неизменна:** PL `Pełny cennik bez ukrytych kosztów`, UK `Повний прайс без прихованих витрат`, RU `Полный прайс без скрытых платежей`. Длинный вариант «Pełny cennik na stronie, bez ukrytych kosztów» отклонён.

### Длина

8. **Строгий максимум — 160 символов** (с `✔`, `☎` и пробелами). Превышение — нарушение стандарта (✕).
9. **Цель — 150–160 символов.**
   - Меньше 150 допускается, если есть причина.
   - Если текст короче 150, нужно проверить, можно ли добавить полезную информацию (ещё одну реальную работу, важное условие).
   - Удлинять текст ради числа символов нельзя.
   - Сокращать без причины, если полезная информация помещается, тоже нельзя.
10. **Ширина в пикселях — рекомендация.** Если текст не помещается в 2 строки сниппета (≈ 2 × 600 px, Arial 14 px), панель предупреждает (◐). Текст автоматически не сокращается.

### Работы

11. **Только конкретные ремонтные работы (действия)** — «Wymiana bębna», «Udrażnianie głowicy», «Naprawa podawania arkuszy». Не перечисляются вместо работ:
    - детали;
    - расходники («kartridże», «papier cukrowy», «toner»);
    - симптомы («smugi», «kropki na obrazie»).
12. **Каждая работа есть в прайсе или FAQ этой страницы.** Чего нет в прайсе, того не пишем, даже если запрос популярен.
13. **2–4 работы — ориентир, а не жёсткое ограничение.** Важнее релевантность, естественный текст и соответствие реальным услугам. Слабые работы ради количества не добавляются.
14. **Порядок — по силе спроса** (раздел 3): самая востребованная работа первой.
15. **Без повтора смысла:** если в тексте есть чистка головки, «konserwacja ogólna» не добавляется. Синонимы одной работы не перечисляются.
16. **Повтор «naprawa / ремонт» допустим**, если первое слово описывает услугу в целом, а второе — конкретную работу: `Serwis i naprawa drukarek ✔ Naprawa głowicy`. Это не ошибка. Проверка повторов смотрит только блоки после первого.

### Бренды, обещания, цены

17. **Без брендов производителей техники** (HP, Zebra, Epson, Bambu Lab, Jura…), даже при сильном спросе.
18. **Названия ПО и прошивок допустимы** (Klipper, Marlin и т.п.), если одновременно:
    - услуга есть в прайсе;
    - название соответствует реальным запросам;
    - оно обозначает конкретную выполняемую работу («Konfiguracja Klippera»).
19. **Только подтверждённые обещания.**
    - Гарантии, сроки и преимущества можно писать, если они подтверждены на странице (прайс, FAQ, условия).
    - Нельзя писать необоснованные обещания. Само слово при этом не запрещено.
    - Отклонены пользователем: «Diagnoza w 15 min» (главная), «Zwykle w 24 h robocze» (подменный принтер → «Nawet w 24 h», как на странице), «bezpłatnie» (оплачиваются отпечатки), «dojazd do klienta» на плоттерах.
    - Панель помечает слова-обещания (◐ «проверить, что подтверждено»), но не запрещает их.
20. **Без цен, скидок и временных акций** — цены на сайте указаны без НДС и меняются.

### Названия и языки

21. **Техника называется так же, как в Title/H1**, в нужном падеже: «komputerów stacjonarnych» (не «PC»), «zasilaczy awaryjnych UPS», UK «ДБЖ (UPS)», RU «ИБП (UPS)».
22. **Хаб раздела** (naprawa-drukarek) перечисляет типы техники вместо работ: «Laserowe, atramentowe, etykiet, plotery».
23. **PL — эталон.** В UK и RU совпадают смысл, работы и их порядок. Дословный перевод не нужен.
24. **Термины UK и RU берутся со страницы** (H1, прайс, FAQ): «абсорбера (памперса)», «чипа DMD», «тракта паперу / тракта бумаги», «кодировщиков», «огляд / осмотр», «шредерів / шредеров».
25. **Лимит для UK и RU тот же — 160.** Если не помещается, сокращаем формулировку, но не убираем работу.

### Процесс

26. **Все изменения — только через SEO-панель** и после утверждения пользователем. Claude сам решений не принимает. Отклонённые варианты (`rejected`) повторно не предлагаются.

## 2. Исключения

Хранятся в `description-decisions.json` у страницы, по образцу Title:
- **`exception`** — согласованное исключение. Проверка шаблона начала («Serwis i naprawa…») к нему не применяется. Город, телефон, концовка, длина, бренды и обещания проверяются всегда.
- **`exceptionPending`** — текст утверждён, но его отличие от стандарта ещё не согласовано.
  - Панель показывает ◐ «Исключение ждёт согласования» и не считает это ошибкой.
  - Текст автоматически не исправляется.
  - Статус согласованного исключения ему без решения пользователя не присваивается.

| Страница | Поле | Отличие |
|---|---|---|
| Главная PL/UK/RU | `exception` | «Serwis i naprawa komputerów, laptopów i drukarek» и «Koszt naprawy uzgadniamy przed rozpoczęciem» вместо работ — вариант пользователя |
| outsourcing-it | `exception` | Не ремонт: «Outsourcing IT i obsługa informatyczna firm», перечислены услуги |
| druk-3d-na-zamowienie | `exception` | Не ремонт: «Druk 3D na zamówienie», перечислены услуги |
| naprawa-drukarek (хаб) | `exception` | Типы техники вместо работ |
| wynajem-drukarek | `exception` | Аренда — не ремонт: начало «Wynajem drukarek i kserokopiarek» вместо «Serwis i naprawa», вместо работ — условия аренды; концовка стандартная |
| drukarka-zastepcza | `exception` | Подменный принтер — не ремонт: начало «Drukarka zastępcza na czas naprawy» вместо «Serwis i naprawa», вместо работ — условия; концовка стандартная, без обещаний сроков |

UPS в UK/RU («ДБЖ (UPS)», «ИБП (UPS)») идёт по шаблону, отдельного исключения не нужно (правило 21).

## 3. Методика исследования новой страницы

Повторно исследование не делается: для 23 существующих страниц результаты — в `description-research/`. Для новой услуги:

1. **Кандидаты** — работы из прайса и FAQ этой страницы Omobonus. Только то, что реально делаем.
2. **Google Ads, отчёт по поисковым запросам:**
   - смотрим показы, клики и конверсии по работам;
   - показы Ads ≠ частотность в Google;
   - конверсии ≠ оплаченные заказы, пока не проверена настройка отслеживания;
   - запросы «сделай сам для модели» (много показов, мало кликов) — слабый сигнал.
3. **SEO-файлы и Keyword Planner.** Разделяем:
   - подтверждённые данные Keyword Planner с источником;
   - неподтверждённые показатели;
   - просто списки ключевых слов.

   Не все числа из прошлогоднего XLSX — статистика Keyword Planner.
4. **Подсказки Google (Autocomplete)** — считается число формулировок, а не частота поиска.
5. **Очистка перед подсчётом (Ads и подсказки).** Исключаем:
   - чужие устройства;
   - покупку товаров;
   - вакансии;
   - обучение;
   - инструкции «сделай сам»;
   - случайные совпадения слов: курьер UPS, «zaparzacz do herbaty», «pralka», «hamulcowy», скачивание Klipper с GitHub и т.п.
6. **Конкуренты в выдаче.**
   - Предпочтительно Google. Если он ограничен (блокирует сбор), используем другие источники и указываем это в исследовании.
   - Количество городов и конкурентов не фиксировано: исследование должно быть достаточным и проверяемым.
   - Отсеиваем агрегаторы, каталоги, производителей, статьи, справочники цен, дубли доменов.
   - Для каждой работы считаем: у скольких конкурентов есть, у скольких стоит первой, есть ли в их Title/Description.
7. **Выбор.** Работа подходит, если она есть в прайсе Omobonus, подтверждена спросом или конкурентами и помещается в 160 символов.
   - **Узкие категории** (мало конкурентов, нет подсказок и Ads): допустим выбор по прайсу, релевантным конкурентам и технической специфике. В исследовании ставим пометку «Слабые данные», выбор согласуем с пользователем.
   - Для таких категорий не требуется подтверждение двумя источниками.
8. **Запасные варианты** записываются в research-файл как отклонённые с причиной («не влезает — запасной №1»).
9. **Спорные варианты** (близкие по силе работы) показываются пользователю с цифрами. Выбор записывается в research-файл: «Решение пользователя <дата>».
10. **Перед предложением** — проверка по разделу 1. Предложение кладётся в `pending.proposals` (`description`, `why`, `works`, `evidence`, `warnings`, при необходимости `exc`).

**Google Search Console — второй этап.**
- Фиксированной даты пересмотра нет.
- При анализе используются реальные запросы, показы, клики и CTR каждой страницы — с учётом позиции и поискового намерения.

## 4. Статусы в панели

- **«Требуют решения»:**
  - новые предложения Claude (`pending.proposals`);
  - проверенные «свои варианты» (`pending.review`);
  - утверждённые тексты, которые на сайте теперь другие.
- **«Без изменений»** — утверждённые и применённые тексты. Повторно не согласуются, даже если у них есть ◐.
- **✕ — нарушение стандарта:**
  - больше 160 символов;
  - нет города или телефона;
  - производитель техники;
  - нет шаблона начала (кроме исключений);
  - не та концовка (кроме `exceptionPending`).
- **◐ — рекомендация:**
  - короче 150;
  - не помещается в 2 строки;
  - город не в стандартной форме;
  - обещание нужно проверить;
  - повтор слова внутри работ;
  - исключение ждёт согласования.
- Автоматически ничего не исправляется.

## 5. Порядок согласования

То же, что для Title (`docs/seo/title-standard.md`, раздел 4):
1. Пользователь в панели нажимает **Утвердить** или **Отклонить** и вписывает «Свой вариант».
2. Нажимает «Скопировать решения для Claude» и вставляет текст в чат.
3. Claude применяет утверждённое на сайте и переносит в `approved` (`description`, `date`, `note`, `length`, `exception?`). Отклонённое предложение дописывает в `rejected`.
4. Свой вариант Claude проверяет по разделу 1 и кладёт в `pending.review` (`own`, `status: ok/fix`, `fix?`, `why`, `exc?`). На сайт он попадает только после повторного утверждения.

## 6. Повторная проверка

1. Ветка `test`, `http://localhost:3000` отвечает.
2. Запустить `node scripts/seo-audit/description-audit.mjs` (`--dry` — без записи в историю):
   - адреса берутся из `sitemap.xml`;
   - Description читаются с сайта и сравниваются с `approved`;
   - в историю пишется число страниц, решений и изменений;
   - собирается панель `%TEMP%\omobonus-seo-panel.html`.
3. Если панель не запущена — `node scripts/seo-audit/serve.mjs`, затем открыть `http://localhost:4100/#description`.
4. Когда проверять: после правок Description, для каждой новой страницы (до слияния), при плановой SEO-проверке.
5. Сайт при проверке не меняется. Commit и push — только по отдельному разрешению.

## 7. Согласованность с Title

- **Общее:**
  - без брендов производителей;
  - техника называется одинаково;
  - PL — эталон;
  - тот же процесс через панель;
  - те же страницы-исключения: главная, Outsourcing IT, 3D на заказ, аренда, подменный принтер. В Title и в Description они утверждены как исключения.
- **Намеренные различия:**
  - город: в Title — суффиксом «| Omobonus Wrocław», в Description — в падеже («we Wrocławiu»);
  - в Description обязательны телефон, блоки `✔` и концовка про прайс;
  - лимиты свои: Title — ориентир 35–60 и обрезка по пикселям, Description — максимум 160 и цель 150–160;
  - Klipper/Marlin в Description допустимы как работа (правило 18); в Title такие названия не используются.
- Первый блок Description повторяет услугу из Title — это намеренно. Дальше текст добавляет новое: работы, прайс, телефон.
