# Аудит настроек и расхода токенов Claude Code и Codex (раз в неделю)

Цель: следить, сколько токенов уходит на постоянную загрузку в каждый чат, и вовремя замечать новые тяжёлые правила, дубли и устаревшие записи. Скрипт только читает файлы, ничего не исправляет.

## Запуск
0. Сначала прочитать журнал «Экономия токенов» (База знаний → Панель и инструменты → Экономия токенов, файл `knowledge/v2/4-panel-i-instrumenty/4-4-ekonomiya-tokenov/7-zhurnaly/zhurnal-optimizacii-tokenov.md`): не повторять закрытое без условия возврата. После запуска — сравнить с прошлыми цифрами и дописать журнал.
1. Выполнить `node C:/Users/Andrii/omobonus-workspace/scripts/token-audit.mjs` (ключ `--no-write` — только показать отчёт, ничего не сохранять).
2. Скрипт проверяет: `CLAUDE.md` (личный и проектный), `MEMORY.md` и файлы памяти, правила `.claude/rules/` без `paths` (грузятся в каждый чат), описания навыков и агентов, MCP, плагины, хуки, дубли строк, ссылки на несуществующие файлы. В том же запуске проверяются настройки обоих ИИ, явные лимиты и отключения сжатия, инструкции передачи Claude и сохранённая передача Codex для сайта и Workspace. Codex читается через существующий `validate-config.cjs`: официальные `config/read` и `hooks/list`, без запроса модели и исполнения хуков. Учёт Codex читается существующим `control.cjs audit`; неизвестный расход не равен нулю.
3. Он сам сравнивает с прошлым снимком, пишет снимок и отчёт в `C:/Users/Andrii/Documents/token-saving/audit/` и дописывает раздел в журнал «Экономия токенов» (`knowledge/v2/4-panel-i-instrumenty/4-4-ekonomiya-tokenov/7-zhurnaly/tehnicheskij-zhurnal.md`). Запись за ту же дату не дублируется.
3а. Скрипт также проверяет индикатор контекста `Blueming.claude-state-bar` в Antigravity IDE (`scripts/indicator-check.mjs`): наличие и версию расширения (1.17.3), 6 настроек и пороги 50/75%, автообновление, локальные правки кода, режим Medium/High и расчёт контекста по последней переписке. Отклонения пишутся в отчёт и журнал, ничего не исправляется; сверку с `/context` сделать вручную (из скрипта недоступна), расхождение больше ~5 пунктов — записать в журнал.
3б. Поиск новых решений в интернете (WebSearch, режим standard; extended — только если находок мало или тема свежая): официальные обновления Anthropic и Claude Code (release notes, changelog, документация), GitHub (issues и релизы `anthropics/claude-code`, новые Skills, хуки, расширения, инструменты), технические статьи по снижению расхода токенов. Сверять с журналом «Экономия токенов» (в т. ч. «Бесполезные проверки»): изученное без новых обстоятельств не повторять. По каждой находке оценить: совместимость с Antigravity IDE, реальную экономию, риски, стоимость внедрения. В отчёт — только новые полезные решения со ссылками на источники; ничего нет — так и написать. Результат записать в журнал (новая запись Т-NN или «Повторно» в старой). Ничего не устанавливать и не менять автоматически: решает владелец. Не пересказывать общеизвестное и не брать непроверенные советы без источника.
3в. Версии и модель (без установки, только чтение): `claude --version` (CLI) и версия расширения `anthropic.claude-code` в `~/.antigravity/extensions` против `antigravity --list-extensions --show-versions`; отставание расширения от CLI — в отчёт. Активная модель Codex — `model` в `~/.codex/config.toml` (сейчас `gpt-6.1-sol`); сменилась или исчезла из доступных — в отчёт. Обновление расширения — только по разрешению владельца.
3г. Ручные команды для владельца (из скрипта недоступны): `/usage` — лимиты и расход, `/storage` — что копится на диске, `/context` — что грузится в чат. В отчёт напомнить сделать их и записать отклонения.
4. Пользователю — короткий итог: сколько токенов грузится постоянно, что изменилось с прошлой недели, есть ли новые правила без `paths`, возможная экономия. Подключения claude.ai (MCP) скрипт не видит — их размер смотреть в `/context`.
4б. Пилот «Читатель» (2026-11-10…2026-11-24): прежний `pilot-reader.mjs` строит раздел отчёта с учётом запусков и СТОП-критериев. В общем аудите всегда `allowStop: false`: даже при СТОП помощник не отключается, владелец получает рекомендацию. На 7-й и 14-й день дать рекомендацию «оставить / улучшить / отключить». Повторные задачи модели — только после оценки расхода и отдельного разрешения. После 2026-11-24 пункт убрать.
5. Обновить дату в таблице `tablica-rabot.md`.

## Отложенные проверки (выполнить при первом случае)
- Хук «База знаний» после настоящего автосжатия контекста: в журнале `/Экономия токенов` (Т-04) проверить, что после сжатия подсказка выдалась заново целиком (в состоянии `%TEMP%/omobonus-kb-hook/<сессия>.json` поле `cc` выросло, `shown` обнулилось). Сжатие искусственно не вызывать. Результат записать в Т-04. До первого настоящего сжатия пункт остаётся открытым.

## Правила
- Это один прежний аудит, напоминание и технический журнал Workspace. Новую периодическую задачу или журнал не создавать. `--no-write` ничего не сохраняет; `--journal-only` сохраняет результат только в существующий технический журнал без нового файла отчёта/снимка. Повтор за ту же дату не дублируется. Дата — Europe/Warsaw.
- Эталоны брать из утверждённых документов Базы знаний и `knowledge/approved-index.md`. Если документ настроек имеет статус `review` и не утверждён в реестре, явно писать «эталон не утверждён»; текущие значения и прошлый снимок не объявлять эталоном. Справочные расхождения помечать отдельно. Журнал содержит дату, факты, отклонения и непроверенные пункты.
- Реальное сжатие, новый чат и задачи модели ради проверки не запускать; работоспособность после сжатия и экономия подтверждаются обычной работой. Лимиты аккаунтов, `/context`, `/usage`, `/status` при недоступности из локального API остаются ручной проверкой.
- Ничего не удалять, не переносить и не сжимать автоматически. Предложения по экономии — только пользователю, правки — после его согласия.
- Новое правило без `paths` больше 2 КБ — сразу сказать пользователю; исправление — по разделу «Проверка на постоянную загрузку» в `docs/claude/dobavit-pravilo.md`.
