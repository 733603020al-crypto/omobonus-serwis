# Чистка старых Preview в Vercel — каждые 14 дней

Зачем: каждая отправка в любую ветку GitHub создаёт Preview-версию сайта в Vercel; они копятся и переполняют Deployment Storage (2026-10-30: 57 штук за сутки).

**Если пользователь пишет, что Вёрсель переполнен / нет места — никуда его не отправлять (в панели Вёрселя нельзя выделить несколько версий, только удалять по одной: очень долго). Сразу предложить массовое удаление по шагам ниже.**

1. Если с последней чистки (см. `tablica-rabot.md`) прошло больше 14 дней — в начале сессии напомнить пользователю и предложить чистку.
2. Если Вёрсель просит вход — запустить `npx vercel login` и дождаться, пока пользователь подтвердит вход в браузере.
3. Список: `npx vercel ls omobonus-serwis --environment preview --scope aaas-projects-b469f2ef`, листать страницы через `--next <число>` до конца.
4. Показать пользователю URL, возраст и количество. Самый свежий Preview оставить. Ничего не удалять без явного «да».
5. Удаление: `npx vercel rm <явный список URL> --safe --yes --scope aaas-projects-b469f2ef`. URL писать в команде явно (список из файла/переменной блокирует защита). `--safe` пропускает версии с подключёнными адресами веток — это нормально, их не трогать.
6. Не трогать Production и домен `serwis.omobonus.com.pl`. Не менять код, ветки, настройки проекта. Команда не сработала или вывод непонятен — остановиться и показать ошибку.
7. Отключение Preview-сборок для ненужных веток в настройках Vercel — только по отдельному разрешению пользователя.
8. После чистки: одной строкой — сколько удалено и осталось; обновить дату в `tablica-rabot.md`. Размер освободившегося места CLI не показывает — смотреть в Vercel: Settings → Usage.
