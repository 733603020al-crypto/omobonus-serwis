# CLAUDE.md

**Главное правило: этот файл должен быть коротким.** Он читается в каждой сессии и тратит токены. Подробности — в файлах `docs/claude/`; читать только нужный по задаче. Новые правила — в подходящий файл ниже, а не сюда.

## Всегда
- **Формат ответов (обязательно, постоянно, для всех задач):** все итоговые отчёты, результаты проверок и ответы на задания выдавать одним цельным Markdown-блоком с кнопкой Copy (единый fenced code block). Весь содержательный ответ — внутри блока, без текста до и после него. Не разбивать ответ на несколько блоков. Это правило главнее любых других правил об оформлении ответов (в том числе в `docs/claude/otvety.md` и личном `~/.claude/CLAUDE.md`).
- Отвечать только по-русски, коротко (2–4 предложения), простым языком, без техжаргона и путей; английские слова — русскими буквами. Задание выполнено — без вопроса в конце.
- Ветка `master` защищена: ничего не менять без явного разрешения на конкретное действие. Commit, push, merge — только после разрешения пользователя. Перед работой молча проверить ветку; не подходит — остановиться и спросить.
- Не читать `.env*`, не ставить пакеты, не менять цены, контакты, юридические тексты, форму, URL/canonical/hreflang без разрешения.
- Задача понятна — выполнять самому, без плана на утверждение; спрашивать только когда непонятно или риск.
- Всё, что можно сделать без человека, делаю сам: не прошу пользователя нажать, обновить, переключить, открыть (например, страницу в браузере обновляю сам, а не пишу «обнови страницу»).
- Задачи Workspace (обязательно): минимум вызовов инструментов и токенов, без повторных и фоновых проверок и запусков; после изменений — одна проверка типов; Chrome и скриншоты — только по разрешению (исключение — `npm run check:ui`, максимум 2 снимка на всю задачу, см. `docs/claude/panel.md`); никаких лишних действий; отчёты краткие.
- Журнал разработки Workspace (обязательно): вести в существующем журнале этапов `AI_WORK_STATE.md`, новый не создавать. После каждой задачи обновить её запись: что сделано, что проверено, что осталось, ошибки, статус. Доработка — правка прежней записи, не дубликат. Перед задачей учесть прежние решения из журнала. Писать кратко, без технического шума.
- Проект на `http://localhost:3000` (`npm run dev:turbo`) должен работать после задачи; сборку — только в копии проекта.
- Служебные отчёты в репозиторий не класть; длинные ответы — HTML-файлом вне проекта.
- Утверждённые правила под задачу подбирает «База знаний» (хук в начале запроса показывает 3–5 нужных файлов; читать их, не все). Противоречие: безопасность и ветки → утверждённые решения → узкий стандарт главнее общего → свежая утверждённая версия. Черновики и заметки — не правила. Список: `omobonus-workspace/knowledge/approved-index.md`.
- В любой задаче сначала открыть `docs/claude/pravila.md`: дерево всех правил и список команд пользователя. По дереву дойти до нужной папки и читать только её.
- Просьба добавить/поправить правило или новое решение без записи в правилах — читать `docs/claude/dobavit-pravilo.md`.

## Единая структура: писать только сюда
Все правила, инструкции и стандарты — только в `CLAUDE.md` (указатель) и файлах `docs/claude/`, `docs/seo/`, `docs/languages/languages-standard.md`, `.claude/rules/`; они видны в панели (Конфигурация ИИ → Правила). Отложенные задачи — только в журнале панели (`omobonus-workspace/tasks`). Новый файл или папку правил создавать только после вопроса пользователю и его разрешения; сначала предложить подходящий существующий раздел и спросить. Это же читает Кодекс (`AGENTS.md`). Новое правило по умолчанию — сюда, в подходящий файл по таблице ниже, а не в личную память (память невидима для панели и других помощников; в неё — только личные предпочтения). Перед записью найти тему по карте в `docs/claude/pravila.md`; темы нет — спросить пользователя. После любой записи или правки правила (даже без просьбы «занеси») ответить «Правило добавлено/изменено» и дать кликабельную ссылку на правило в панели (без описания места словами).
